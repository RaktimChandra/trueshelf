    Bugs our own tests caught

    We think this matters more than any accuracy number: the tests found real defects, and each fix is now guarded by a test.

    Unit test

    Star ratings leaked into hotel names

    Sahara Direct writes “Noor Al View Inn 5*”. Our cleaning regex failed on the *, so a stray “5” stayed in the name and faked a “numbers differ” signal between records of the same hotel.

    Dubai held-out F1 0.9967after fix 0.9987
    Stress test

    Unreadable room names were merged together

    We added a supplier style the room grammar had never seen (French, marketing names, “Room Type C”). The first run produced 644 wrong merges: partly-read names were grouped on the parts we could read. Fix 1 isolates any name missing a class or bed (158 left). Fix 2 also isolates names with leftover unread words, and orders patterns longest-first so “river” isn't read as “riv” + “er”.

    644 wrong merges1580
    Determinism test

    Results changed between identical runs

    Python randomises set ordering per process, which changed which rare words were used for blocking and the order of floating-point sums. Same code, same data, different F1. Fixed with stable tie-breaks and ordered sums; a test now runs the whole pipeline twice and requires identical rankings.

    F1 varied run to runidentical across hash seeds
    Parity test

    Browser and engine must agree to the rupee

    The prototype re-prices and re-ranks in the browser so the assumption sliders work live. A test runs the JavaScript under Node and compares every like-for-like price and every rank with Python, including Python's banker's rounding, which JavaScript doesn't do by default.

    3 cities, every offer, exact match
    Our mistake

    One failure was the test itself

    A unit test expected a supplier-risk cost above ₹500; the formula correctly gives ₹370. We fixed the test, not the code, and wrote the arithmetic into it.

    Reproduce everything

    Seeds are fixed (world 7, feeds 11, offers 23–25, bookings 31, sightseeing 41), the configuration is versioned (2026.11-r1), and results are identical across runs.

    Honest limits

    What is real

    The engine, the held-out evaluation protocol, the tests, the failure modes we generate (transliteration, abbreviations, typos, swapped coordinates, sister properties 80–250 m apart, rate-plan words inside room names), and every number on this page.

    What is not yet

    All hotels, suppliers and bookings are synthetic, because teams don't get TBO feeds. Real feeds will be messier. Rupee values in like-for-like pricing are stated assumptions. Ranking impact on conversion is untested. Round 2 starts with a shadow-mode pilot on one city's real feed.
